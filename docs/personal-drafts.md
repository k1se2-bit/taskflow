# Быстрое создание и локальный черновик

Новая личная задача создаётся через существующие кнопки на «Сегодня» и в полном личном списке. Обязателен только заголовок «Что нужно сделать?». Срок выбирается быстрыми вариантами «Сегодня», «Завтра», «Без срока» либо календарём. Описание и приоритет находятся в блоке «Подробнее».

## Черновик

Для каждого UID на устройстве хранится один черновик новой личной задачи. Он включает название, описание, приоритет, срок и постоянный ID будущей задачи. Восстановление выполняется при следующем открытии формы создания. Редактирование существующей задачи не использует этот черновик и не получает автоматического сохранения изменений. Командные формы не изменяются.

Запись выполняется после короткой паузы ввода, при обычном выходе из формы и при переходе приложения в фон. Используется приватная директория приложения: запись во временный файл с flush, затем переименование; операции выполняются последовательно. Повреждённый файл не удаляется молча: предлагаются повторная загрузка либо явный сброс. При обычном выходе с ошибкой записи приложение спрашивает, остаться ли в форме.

Черновик не синхронизируется с другими устройствами и не является серверной задачей. Удаление приложения или очистка его данных удаляет локальные черновики. Содержимое не шифруется этим модулем; приватная директория не заменяет шифрование и не защищает от доступа к скомпрометированному устройству. Не обещается сохранение последних символов при аварийном завершении процесса до окончания записи.

## Сохранение задачи

Для новой задачи сначала записывается черновик, затем выполняется Firestore-транзакция с постоянным ID. Если документ уже существует с теми же полями, повторная попытка не создаёт другую задачу и не сбрасывает её статус. Если существующий документ отличается, перезапись блокируется с сообщением: нужно проверить список и явно создать другую задачу.

Создание новой задачи теперь требует соединения для подтверждения транзакции. Без сети черновик остаётся на устройстве; задача не показывается как подтверждённая сервером. Это осознанное изменение относительно прежней постановки записи в очередь. Редактирование существующих задач сохраняет прежний механизм update. После успешного создания черновик очищается. При ошибке очистки пользователь получает предупреждение; постоянный ID сохраняет защиту от повторного создания под другим ID.

## Проверка

1. Начните новую задачу, введите название и описание, выберите «Завтра».
2. Выйдите назад, откройте создание снова: поля должны восстановиться.
3. Перезапустите приложение и проверьте восстановление на том же устройстве.
4. В другом аккаунте тот же черновик не должен показываться.
5. Сохраните задачу при наличии сети: она появляется в списке, следующая новая форма пустая.
6. Проверьте явный сброс с подтверждением и сохранение обычных задач после сброса.
7. Без сети проверьте сохранение локального черновика; не считайте сетевое создание успешным до подтверждения.
8. Проверьте, что редактирование старой задачи не заменяет черновик новой.

Добавлены восемь тестов файлового хранилища и модели. Они не заменяют widget-тесты формы, испытания аварийного завершения и тесты транзакции в реальном Firebase. Результаты сборки, тестов и ручной проверки нужно подтвердить отдельно. Правила Firestore и схема серверных задач не изменяются.
