# Сборка Android APK в GitHub

Workflow `Android debug APK` запускается вручную. Он анализирует Dart-код, запускает Flutter-тесты, собирает debug APK и сохраняет его как артефакт на 7 дней. Он не публикует приложение в Google Play и не разворачивает правила Firebase. Сборка обращается к зависимостям и инструментам, но не запускает приложение и не изменяет данные Firestore.

## Однократная настройка Firebase

1. На своём компьютере откройте `android/app/google-services.json` рабочего проекта TaskFlow.
2. В GitHub откройте репозиторий `k1se2-bit/taskflow`.
3. Перейдите в `Settings` → `Secrets and variables` → `Actions` → `New repository secret`.
4. Укажите имя `GOOGLE_SERVICES_JSON`.
5. В значение вставьте всё содержимое файла JSON без изменений и сохраните. Нужен обычный текст JSON, не Base64.

Не используйте ключ сервисного аккаунта, файл с `private_key`, пароль или ключ подписи приложения. Нужен именно Android-конфиг, полученный из Firebase. Он должен соответствовать `lib/firebase_options.dart` и Android application ID `com.example.taskflow`. Workflow не выводит содержимое секрета в лог и не добавляет JSON в исходный код. Однако клиентская Firebase-конфигурация входит в собранный APK; защита данных обеспечивается правилами доступа, а не сокрытием конфигурации клиента.

## Запуск

1. Откройте вкладку `Actions`.
2. Выберите `Android debug APK`.
3. Нажмите `Run workflow`, выберите `main` и подтвердите запуск.
4. Дождитесь успешного завершения.
5. Внизу страницы запуска найдите артефакт `taskflow-debug-<номер запуска>`.
6. Сохраните архив, распакуйте его и получите `app-debug.apk`.

Если этап восстановления Firebase завершился ошибкой, проверьте наличие секрета и корректность JSON. Если упали анализ, тесты или сборка, исправьте соответствующую ошибку в логе; APK при неудачной проверке не публикуется.

## Установка и ограничения

Для установки на личный Android-телефон может потребоваться разрешение установки из выбранного источника. Это debug-сборка для разработки и проверки, а не подписанный релиз для распространения.

Ключ debug-подписи в GitHub может отличаться от ключа локальной сборки и от ключа следующего запуска. Поэтому Android может отказать в обновлении уже установленной копии. Не удаляйте рабочую копию вслепую: сначала проверьте синхронизацию данных и используйте отдельный тестовый телефон или эмулятор. Удаление приложения удаляет его локальные данные и настройки.

Артефакт доступен пользователям с соответствующим доступом к GitHub Actions. Учитывайте видимость репозитория. Запуск расходует минуты и хранилище Actions согласно тарифу аккаунта. Постоянный ключ подписи и release-сборка должны настраиваться отдельно.
