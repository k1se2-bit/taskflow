# Демонстрация TaskFlow на двух эмуляторах

## Подготовка

Используйте два отдельных виртуальных устройства Android Studio. В первом войдите в тестовый аккаунт владельца A, во втором — в тестовый аккаунт участника B. На обоих устройствах должен быть доступ к сети. Не используйте реальные персональные данные и не показывайте пароли при записи экрана.

Запишите перед демонстрацией:

- дату проверки;
- SHA кода: результат `git rev-parse HEAD`;
- для APK из GitHub — номер запуска `Android debug APK` и SHA этого запуска;
- Android API и названия двух AVD;
- источник установки: локальный Flutter либо APK из Actions.

Не смешивайте результат проверки локальной сборки с результатом установки другого APK. Для живого показа можно заранее создать команду и принять B, а создание и одобрение показать отдельным фрагментом.

## Основная демонстрация: 7–10 минут

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | A создаёт личную задачу «Личная подготовка» | Она видна у A и отсутствует у B |
| 2 | A создаёт команду «Демо TaskFlow» и копирует ID | Команда создана, A — владелец |
| 3 | B отправляет заявку по ID со своим тестовым именем | A видит заявку; доступа до одобрения у B нет |
| 4 | A принимает заявку и при необходимости меняет имя B | Команда появляется у B, имя сохраняется |
| 5 | A назначает B задачу «Подготовить отчёт» со сроком на сегодня | Задача появляется у B после синхронизации |
| 6 | B открывает командный календарь и выбирает сегодняшний день | Назначенная задача отображается |
| 7 | B меняет статус на «В работе» | A видит изменение, сводка остаётся согласованной |
| 8 | A использует поиск, статус и фильтр исполнителя, затем сбрасывает фильтры | Список меняется по условиям и восстанавливается |
| 9 | B открывает «Уведомления», проверяет разрешение и задаёт время на несколько минут вперёд | Время сохраняется, появляется ожидающее напоминание |
| 10 | Оба аккаунта остаются авторизованными, B сворачивает приложение | Уведомление приходит; возможна задержка Android |
| 11 | B возвращается и обновляет счётчик | Показанное уведомление больше не должно числиться ожидающим |
| 12 | B завершает задачу | A видит «Выполнена» и изменение прогресса |

Не обещайте показ точно до секунды. Ожидание уведомления можно использовать для объяснения ролей и архитектуры либо показать отдельной записью.

## Отдельная проверка переназначения и отмены

1. A создаёт вторую активную задачу и назначает её B.
2. B задаёт напоминание с достаточным запасом времени.
3. Не выходя из аккаунтов, A переназначает задачу себе.
4. Оба приложения должны успеть синхронизироваться до наступления напоминания.
5. Проверьте: у B задача исчезла из доступных назначений, у A появилась.
6. Проверьте уменьшение очереди ожидающих напоминаний B. Настройка B не переносится A.
7. До исходного времени убедитесь, что очередь B не содержит отменённое напоминание; после времени проверьте отсутствие его показа.

Выход из аккаунта B не является заменой этой проверки: выход сам отменяет локальные уведомления. Отключение сети — отдельный сценарий с известным ограничением, а не основание обещать мгновенную отмену.

## Снимки экрана для отчёта

Рекомендуемые кадры: личные задачи; заявка и её одобрение; команда с участниками; назначенная задача на двух устройствах; командный календарь; поиск и сводка; сохранённое время напоминания; уведомление в шторке; итоговый статус и прогресс. Эти кадры нужно получить при демонстрации — документация не содержит и не подменяет доказательства снимками-заглушками.

## Форма протокола

Для каждого шага заполните строку:

| Шаг | Дата и время | Устройство / аккаунт | Фактический результат | Пройден / ошибка / не проверен | Скриншот или лог |
| --- | --- | --- | --- | --- | --- |
| 1 | | | | Не проверен | |

При ошибке зафиксируйте шаг, текст сообщения и последовательность действий. До проверки на физическом устройстве не отмечайте её выполненной. Успешные UI-сценарии не заменяют тесты правил безопасности.

## Короткое объяснение архитектуры

TaskFlow использует Flutter для интерфейса, Firebase Authentication для аккаунтов и Firestore для личных и командных данных. Права владельца и исполнителя ограничиваются правилами Firestore, а не только видимостью кнопок. Время командного напоминания хранится в личном документе пользователя; уведомления планируются локально на устройстве. Исходные правила тестируются отдельно на Firestore Emulator, без изменения рабочей базы.

Подробности готовности и ограничения перечислены в [контрольной версии](checkpoint.md).
